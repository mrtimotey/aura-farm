2. Теоретическая часть

2.1. Что такое файловая система?

Файловая система — это порядок, определяющий способ организации, хранения и именования данных на носителях информации. Она определяет, как данные будут храниться на диске, как к ним будет осуществляться доступ и как они будут структурированы.

Ключевые понятия:

  • Файл — поименованная область на носителе, содержащая данные.
  • Папка (каталог, директория) — контейнер для группировки файлов и других папок.
  • Путь — последовательность папок, указывающая местоположение файла.
  • Корневой каталог — начальная точка файловой системы (например, C:\ в Windows, / в Linux).

Файловая система имеет иерархическую (древовидную) структуру:

C:\ (корень)
├── Users\
│   ├── Student\
│   │   ├── Documents\
│   │   ├── Downloads\
│   │   ├── Desktop\
│   │   └── Pictures\
│   └── Public\
├── Program Files\
│   ├── Microsoft Office\
│   └── Google Chrome\
└── Windows\
    ├── System32\
    └── Temp\

⚠️ Важно: Каждый файл и папка имеют уникальное полное имя (путь), которое однозначно определяет их местоположение в файловой системе.

2.4. Атрибуты файлов

Атрибуты файла — это дополнительные параметры, определяющие свойства файла и права доступа к нему.

  • 📖 Только чтение (Read-only) — файл можно открыть и прочитать, но нельзя изменить или удалить.
  • 👁️ Скрытый (Hidden) — файл не отображается в проводнике при стандартных настройках.
  • ⚙️ Системный (System) — файл используется операционной системой. Не рекомендуется изменять.
  • 📦 Архивный (Archive) — файл был изменён с момента последнего резервного копирования.

2.6. Поиск и сортировка файлов

Поиск файлов

  • По имени файла
  • По расширению (*.txt, *.docx)
  • По дате создания/изменения
  • По размеру файла
  • По содержимому (для текстовых файлов)

Сортировка файлов

  • По имени (A-Z, Z-A)
  • По дате изменения
  • По типу файла
  • По размеру
  • По дате создания

💡 Совет: Используйте маски поиска для более точного поиска: * — любое количество символов (например, *.txt — все текстовые файлы), ? — один любой символ (например, file?.docx — file1.docx, file2.docx).

2.7. Что такое командная строка?

Командная строка (Command Line Interface, CLI) — интерфейс, в котором пользователь взаимодействует с компьютером путём ввода текстовых команд.

Преимущества командной строки:

  • Высокая скорость выполнения операций
  • Возможность автоматизации (скрипты)
  • Доступ к функциям, недоступным в графическом интерфейсе
  • Минимальное потребление ресурсов

Основные командные оболочки

Оболочка ОС Особенности
CMD Windows Классическая командная строка, базовые команды
PowerShell Windows Объектно-ориентированная, расширенные возможности
Bash Linux, macOS Стандартная оболочка Unix, мощные скрипты
Zsh Linux, macOS Расширенная оболочка с автодополнением

Синтаксис команд: команда [ключи] [аргументы]

Пример: dir /a /s C:\Users

  • Ключи (флаги) — уточняют поведение команды (обычно начинаются с / или -).
  • Аргументы — данные, над которыми выполняется операция (файлы, папки, адреса).

2.11. Конвейеры и перенаправление ввода-вывода

Конвейер (pipe) — оператор |, передающий вывод одной команды на вход другой.

Перенаправление вывода:

  • > — записать вывод в файл (перезапись)
  • >> — добавить вывод в файл
  • < — читать ввод из файла
  • 2> — перенаправить ошибки

Примеры:

dir | findstr ".txt"          — найти все .txt файлы
tasklist | findstr "chrome"    — найти процессы Chrome
dir > files.txt                — сохранить список файлов в файл
ping google.com >> log.txt     — добавить результат пинга в лог

2.13. OpenServer и MySQL

OpenServer — это портативная серверная платформа для Windows, включающая Apache, Nginx, MySQL, PHP и другие компоненты.

Компоненты OpenServer:

  • Apache/Nginx — веб-серверы
  • MySQL/MariaDB — системы управления базами данных
  • PHP — язык программирования для веб-разработки
  • phpMyAdmin — веб-интерфейс для управления MySQL
  • Redis, Memcached — системы кэширования

MySQL — это свободная реляционная система управления базами данных, одна из самых популярных в мире.

Основные функции СУБД:

  • Создание базы данных (описание структуры, связей, данных)
  • Наполнение и обновление данных
  • Анализ данных
  • Защита данных от несанкционированного доступа
  • Обеспечение целостности данных
  • Управление транзакциями
  • Восстановление после сбоев

БД — база данных. СУБД — система управления базами данных. ER — сущность-связь.

2.15. Ограничения целостности MySQL

Ограничения целостности — это правила, которые гарантируют корректность данных в таблице.

Ограничение Назначение
PRIMARY KEY Первичный ключ. Уникально идентифицирует каждую строку таблицы. Не может быть NULL. Может быть составным.
FOREIGN KEY Внешний ключ. Обеспечивает ссылочную целостность между таблицами.
NOT NULL Запрещает вставку NULL в столбец.
UNIQUE Обеспечивает уникальность значений в столбце.
CHECK Проверяет выполнение логического условия (MySQL 8.0+).
DEFAULT Значение по умолчанию для столбца.
AUTO_INCREMENT Автоматическое увеличение значения (для целочисленных ключей).
ON DELETE CASCADE Каскадное удаление связанных записей.

⚠️ Важно: При попытке вставить запись с несуществующим внешним ключом запрос завершится ошибкой.

2.16. Синтаксис CREATE TABLE

CREATE TABLE имя_таблицы (
    столбец1 тип [ограничения],
    столбец2 тип [ограничения],
    ...
    [табличные ограничения]
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

⚠️ Важно: Для поддержки внешних ключей и транзакций необходимо использовать движок InnoDB.

Пример:

CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE,
    birth_date DATE,
    gpa DECIMAL(3, 2) CHECK (gpa >= 0 AND gpa <= 5),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

2.17. Синтаксис INSERT, UPDATE, DELETE

-- Вставка данных
INSERT INTO имя_таблицы (столбец1, столбец2, ...)
VALUES (значение1, значение2, ...);

-- Обновление данных
UPDATE имя_таблицы
SET столбец1 = значение1, ...
WHERE условие;

-- Удаление данных
DELETE FROM имя_таблицы
WHERE условие;

⚠️ Важно: UPDATE и DELETE без WHERE затрагивают все строки таблицы.

2.18. Транзакции в MySQL

Транзакция — это последовательность операций, которая выполняется как единое целое. Либо все операции выполняются успешно, либо ни одна из них.

START TRANSACTION;
    -- операции
COMMIT;  -- подтвердить транзакцию
-- или
ROLLBACK;  -- откатить транзакцию

Свойства транзакций (ACID):

  • Atomicity (Атомарность) — все или ничего
  • Consistency (Согласованность) — переход из одного корректного состояния в другое
  • Isolation (Изоляция) — параллельные транзакции не влияют друг на друга
  • Durability (Долговечность) — после COMMIT изменения сохраняются

COMMIT — фиксирует изменения. ROLLBACK — откатывает изменения.

2.19. Индексы в MySQL

Индекс — это структура данных, которая ускоряет поиск и сортировку записей в таблице.

Типы индексов

  • PRIMARY — первичный ключ
  • UNIQUE — уникальный индекс
  • INDEX — обычный индекс
  • FULLTEXT — полнотекстовый поиск
  • SPATIAL — пространственный индекс
CREATE INDEX idx_name ON table_name (column_name);
DROP INDEX idx_name ON table_name;

2.21. Этапы проектирования базы данных

Проектирование базы данных — это последовательный процесс перехода от неформального описания предметной области к формализованной схеме базы данных.

  1. Системный анализ предметной области — подробное словесное описание объектов и связей между ними. Определение границ предметной области.
  2. Построение инфологической (концептуальной) модели — формализованное описание предметной области в терминах «сущность-связь». ER-диаграмма.
  3. Даталогическое проектирование — преобразование ER-модели в реляционную схему: таблицы, поля, ключи, связи.
  4. Физическое проектирование — реализация базы данных в конкретной СУБД (MySQL, PostgreSQL). Настройка индексов, типов данных.

2.22. Основные понятия ER-моделирования

  • Сущность (Entity) — любой различимый объект предметной области, информацию о котором необходимо хранить в БД. Примеры: Студент, Книга, Заказ, Товар.
  • Атрибут (Attribute) — поименованная характеристика сущности, описывающая её свойство. Примеры: ФИО, дата рождения, цена.
  • Ключ (Key) — минимальный набор атрибутов, однозначно идентифицирующий экземпляр сущности. Примеры: Номер зачётки, ISBN, ID.
  • Связь (Relationship) — ассоциация между двумя или более сущностями. Пример: Студент учится в Группе.

Отношение в реляционной БД — таблица.

2.23. Типы атрибутов

Простой (атомарный) Неделимое значение Возраст, Цена

2.24. Типы связей

  • Один к одному (1:1) — каждому экземпляру сущности А соответствует ровно один экземпляр сущности В, и наоборот. Пример: Студент — Зачётная книжка. Реализация: внешний ключ в одной из таблиц с ограничением UNIQUE.
  • Один ко многим (1:N) — одному экземпляру сущности А соответствует 0, 1 или несколько экземпляров сущности В. Пример: Группа — Студенты. Реализация: внешний ключ в таблице «многие».
  • Многие ко многим (N:M) — одному экземпляру сущности А соответствует несколько экземпляров сущности В, и наоборот. Пример: Студенты — Дисциплины. Реализация: промежуточная (связующая) таблица с двумя внешними ключами — всего три таблицы.

2.25. Нотации ER-диаграмм

Нотация Чена (Chen) — классическая нотация, удобна для концептуального моделирования:

  • Прямоугольник — сущность
  • Овал — атрибут
  • Ромб — связь
  • Подчёркнутый атрибут — ключ
  • Линии — соединения

Нотация Crow's Foot («вороньи лапки») — современная нотация, используется в CASE-средствах (MySQL Workbench, ERwin):

  • Прямоугольник — сущность с атрибутами внутри
  • Линия — связь
  • «Вороньи лапки» — сторона «многие»
  • Поперечная черта — сторона «один»
  • Кружок — необязательность (0)

2.26. Нормализация базы данных

Нормализация — это процесс приведения структуры базы данных к нормальным формам с целью устранения избыточности и аномалий.

  • 1НФ (Первая нормальная форма)
    • В таблице нет дублирующих строк
    • В каждой ячейке атомарное значение
    • В столбце данные одного типа
    • Нет повторяющихся групп столбцов
  • 2НФ (Вторая нормальная форма)
    • Таблица в 1НФ
    • Таблица имеет первичный ключ
    • Все неключевые столбцы зависят от полного ключа (если он составной)
  • 3НФ (Третья нормальная форма)
    • Таблица во 2НФ
    • Отсутствует транзитивная зависимость
    • Неключевые столбцы не зависят от других неключевых столбцов

Транзитивная зависимость — неключевой атрибут зависит от другого неключевого атрибута, а не напрямую от ключа (group_name → speciality_name → faculty_name).

2.27. Преобразование ER-модели в реляционную схему

Правила преобразования:

  • Каждая сущность → таблица
  • Каждый простой атрибут → столбец таблицы
  • Составной атрибут → несколько столбцов
  • Ключ сущности → PRIMARY KEY
  • Связь 1:1 → внешний ключ в одной из таблиц с UNIQUE
  • Связь 1:N → внешний ключ в таблице со стороны «многие»
  • Связь N:M → промежуточная таблица с двумя внешними ключами
  • Многозначный атрибут → отдельная таблица

2.29. Мелочи, которые часто спрашивают

  • 1 байт = 8 бит · 1 Кбайт = 1024 байта · 2 Кбайта = 2048 байт · 2 байта = 16 бит
  • Копирование оставляет исходник, перемещение — удаляет; файл, удалённый из корзины, удаляется безвозвратно.
  • ls -l / ls -la — список с деталями (Linux); dir /a — аналог в CMD.
  • netstat — соединения и порты; ipconfig /all — IP-адрес; tasklist — процессы; nslookup — DNS.
  • del удаляет файл, rmdir — папку (CMD); rm — файл (Linux).
  • UNIQUE гарантирует уникальность, PRIMARY KEY может быть составным, AUTO_INCREMENT автоматически увеличивает значение.

2.30. Сетевые протоколы (семинар 9 — про запас)

📌 В вариантах КТ2 вопросов по сетям нет; блок можно вырезать.

  • Wireshark — свободный анализатор сетевых протоколов с открытым исходным кодом, позволяющий перехватывать и интерактивно просматривать трафик.
  • Панели: инструментов, фильтров отображения, список пакетов, детали пакета, байты пакета, строка состояния.
  • Фильтры захвата применяются до начала захвата: host 192.168.1.1, net 192.168.1.0/24, port 80, tcp, udp, icmp, arp.
  • Фильтры отображения применяются после захвата: ip.addr == 192.168.1.1, tcp.port == 80, tcp.flags.syn == 1, http.request.method == "GET", dns.qry.name contains "google", !arp, tcp.analysis.retransmission.
  • Ethernet-кадр: MAC получателя 6 байт · MAC отправителя 6 байт · Тип/Длина 2 байта · Данные 46–1500 байт · FCS 4 байта. Типы: 0x0800 — IPv4, 0x0806 — ARP, 0x86DD — IPv6, 0x8100 — VLAN.
  • IPv4: TTL — время жизни пакета (максимум 255 хопов); Protocol — протокол верхнего уровня (1 = ICMP, 6 = TCP, 17 = UDP).
  • Трёхстороннее рукопожатие TCP: SYN → SYN-ACK → ACK. Флаги: SYN — установка, ACK — подтверждение, FIN — закрытие, RST — сброс.
  • Протоколы: ARP — IP → MAC (запрос broadcast, ответ индивидуальный); ICMP — диагностика (ping, traceroute); DNS — имя → IP, порт 53; TCP — надёжная передача с установкой соединения; UDP — быстрая передача без установки соединения.
  • Аномалии: TCP Retransmission, TCP Dup ACK, TCP ZeroWindow, Out-of-Order, RST.

FROM student_discipline sd
JOIN disciplines d ON sd.discipline_id = d.discipline_id
GROUP BY d.discipline_id;
